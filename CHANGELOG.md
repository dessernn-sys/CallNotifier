Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),

## [1.5.0] - 2026-10-15

Итерация стабилизации и UX-улучшений после развёртывания 1.4.2.
Клиенты переходят на **стабильное имя `.exe`** (без версии), что
позволяет автообновлению подменять содержимое, не ломая ярлыки
и автозапуск. Добавлена защита от нескольких багов, выявленных в поле.

### Добавлено

- **Устойчивость клиента к отсутствию аудиоустройства** (`audio.py`):
  - `pygame.mixer.init()` обёрнут в try/except — при сбое клиент **не падает**,
    а продолжает работать без звука.
  - Фоновый поток раз в 30 сек пытается поднять звук — как только
    аудиоустройство появится, воспроизведение включится автоматически.
  - Кнопка **«🔊 Переподключить звук»** в настройках клиента (F1) — для
    ручного подъёма, если автоподъём не сработал.
  - В настройках клиента (F1) отображается текущий статус:
    «🔊 Звук: доступен» / «🔇 Звук: НЕДОСТУПЕН».
- **Автоматическое закрытие вызовов по `live_time_min`** (`database.py`):
  - Если у типа вызова задано `live_time_min > 0`, то через указанное
    количество минут после создания вызов **автоматически закрывается**.
  - Если `live_time_min == 0` — вызов ждёт явного `stop` от АСистем.
  - Логика применяется «на лету» при `/sync` и в админке, без отдельного
    фонового потока — задержка закрытия ≤ 5 сек.
- **Многострочное поле «Дополнительная информация»** в форме создания
  вызова (веб-админка, таб «Создать вызов»). Переведено с `<input>` на
  `<textarea rows="4">` с возможностью вертикального растягивания.

### Исправлено

- **Спам-воспроизведение складских алертов** при первом запуске клиента
  (один и тот же файл скачивался 4 раза подряд).
  Причина: `_download_wh_alert` работал в отдельном потоке, но
  `_played_reminders.add(alert_key)` вызывался только **после** скачивания.
  За это время цикл синхронизации (каждые 5 сек) успевал запустить
  **несколько потоков** на один и тот же файл.
  Решение: добавлен `set` «файлы в процессе скачивания» (`_downloading`)
  с блокировкой; перед запуском скачивания проверяется, не качается ли
  файл уже.
- **Клиент падал с `pygame.error: WASAPI can't find requested audio endpoint`**
  при отключённых наушниках / отсутствии звуковой карты — весь клиент
  не запускался. Теперь — graceful degradation (см. выше).

### Изменено

- **`config.py`**: `__version__ = "1.5.0"`.
- **`gui/dialogs.py`**: в вкладке «Звук и связь» появилась секция
  «Аудиоустройство» со статусом и кнопкой переподключения.
- **`audio.py`**: рефакторинг `_player_worker` — пропускает воспроизведение,
  если звук недоступен (очередь не забивается).
- **`database.py`**: `get_open_calls` теперь выполняет **два** `UPDATE` —
  по `forced_close_time` и по `live_time_min` (через подзапрос к `types`).

### Совместимость

- **Python:** 3.11.9
- **PyInstaller:** 6.22.3
- **Сервер и клиент:** минорные версии в пределах `1.x.x` совместимы.
- **Миграция:** схема БД не менялась, миграции не требуются.

### Известные ограничения

- Автообновление не работает, если клиент запущен из-под Python (`sys.frozen == False`).
- Клиенты на версиях **< 1.4.0** не имеют встроенного updater'а и обновляются **вручную**.
- Тест спам-воспроизведения складских алертов отложен до реального
  выхода склада в красную зону.

## [1.4.2] - 2026-10-15

Промежуточный релиз. Объединяет изменения между `1.2.0` и `1.4.2`:
работы по автообновлению клиента, устранение серии багов, выявленных в поле.

### Добавлено

- **Автообновление клиента** (`client_updater.py`):
  - Фоновая проверка `GET /api/v1/version` при старте и далее раз в N часов (по умолчанию 6).
  - Диалог подтверждения обновления с прогресс-баром загрузки.
  - Headless-режим (обновление без диалога).
  - Скачивание `.exe` с проверкой **sha256** и retry-логикой (до 3 попыток по умолчанию).
  - Batch-скрипт для замены `.exe` и перезапуска клиента.
  - Резервная копия `.exe.old` — для аварийного отката.
  - Подробный `update.log` в `%APPDATA%\CallNotifier\update\`.
- **Бейдж «🔔 Доступно обновление»** в хедере клиента (показывается, если серверная версия строго больше локальной).

### Исправлено

- **`TypeError: _write_batch() missing 1 required positional argument: 'new_exe'`** — несоответствие сигнатуры метода.
- **`Failed to load Python DLL`** при запуске нового `.exe` после автообновления — устранено наследование переменных окружения PyInstaller (`_MEIPASS2`, `_MEIPASS`) через batch-скрипт. Решение:
  - updater формирует чистое `env` и передаёт его в `Popen(batch)`.
  - batch переписан без `setlocal` (иначе очистка не долетает до дочернего процесса).
  - запуск нового `.exe` идёт через `cmd /c "set _MEIPASS2= && set _MEIPASS= && start ..."`.
  - добавлена проверка размера файла после копирования (защита от недописанного/заблокированного антивирусом `.exe`).
- **`ValueError: size mismatch`** при обновлении — устранено добавлением паузы 5 сек после копирования (даёт антивирусу отпустить хэндл).

### Изменено

- **`client_updater.py`**:
  - `_download_one`: добавлен `flush()` + `fsync()` перед закрытием файла.
  - `_check_and_maybe_update`: формирование чистого `env` для `Popen`.
  - `_write_batch`: переработан batch-скрипт (см. выше).
- **`config.py`**: `__version__ = "1.4.2"`.

### Совместимость

- **Python:** 3.11.9
- **PyInstaller:** 6.22.3 (для сборки клиента)
- **Сервер и клиент:** минорные версии в пределах `1.x.x` совместимы.

### Известные ограничения

- Автообновление не работает, если клиент запущен из-под Python (`sys.frozen == False`).
- Пользователи на версиях **< 1.4.0** не имеют встроенного updater'а и обновляются **вручную**.

## [1.2.0] - 2026-10-12

### Добавлено
- **Словарь произношений и ударений**:
  - Таблица `pronunciation` в БД (`source`, `replacement`, `kind`).
  - CRUD через админку (таб «🔤 Словарь TTS»).
  - Автомиграция из старого хардкода (`LATIN_ABBR_DICT`, `STRESS_DICTIONARY`).
  - Применяется мгновенно — TTS перечитывает словарь при изменении.
  - Регистронезависимо для обоих типов (`replace`, `stress`).
- **Шаблоны TTS** для новых вызовов и напоминаний:
  - Таблица `tts_templates` в БД (`type`, `new_call_template`, `reminder_template`).
  - Визуальный редактор в админке (таб «📝 Шаблоны TTS»).
  - Плейсхолдеры: `{name}`, `{equipment}`, `{info}`, `{info_part}`, `{type}`, `{type_desc}`.
  - Превью на лету с тестовыми данными.
  - Кнопки быстрой вставки плейсхолдеров в активное поле.
  - Кнопка «Сбросить к дефолтному».
- **Выбор голоса Silero** (таб «🎙 Настройки TTS»):
  - 5 голосов: `xenia`, `aidar`, `baya`, `kseniya`, `eugene`.
  - Хранение в `config_server.json` (секция `tts.speaker`).
  - Применяется мгновенно, переживает перезапуск сервера.
- **Кнопка «Очистить кэш TTS»** — удаление всех WAV из `audio_cache/`.
- **Дефолтные шаблоны TTS включают `{info_part}`** — комментарий озвучивается по умолчанию.

### Исправлено
- **Дублирование вызовов** в `/api/v1/sync` — в `_process_server_data` было два подряд `result_calls.append(call)`. Оставлен один.
- **`render_template` — порядок подстановки**: `{info_part}` обрабатывается до `{info}`, чтобы не было конфликта.
- **Чистка пунктуации в шаблонах**: убираются висячие запятые и пробелы перед знаками препинания (`re.sub`).

### Изменено
- **`config_server.json`**: добавлена секция `tts` (`{"speaker": "xenia"}`).
- **`tts_service.py`**: `TTSService.__init__` принимает `config`, читает `tts.speaker`.
- **`server.py`**: `TTSService(db=db, config=config)` — передаётся ссылка на конфиг.

### Совместимость
- **Python:** 3.11.9
- **PyInstaller:** 6.22.3
- **Сервер и клиент:** минорные версии в пределах `1.x.x` совместимы.
- **Миграция:** словарь произношений и шаблоны TTS автоматически создаются при первом запуске сервера (таблицы + дефолтные значения).

## [1.1.0] - 2026-10-07

### Добавлено
- **Механизм версий клиента**: `GET /api/v1/version`, `server_version` в `/api/v1/sync`,
  бейдж «🔔 Доступно обновление» в хедере клиента.
- **Пер-клиентские напоминания вызовов**: трекер `_last_reminder_sent[(client_id, external_id)]`,
  идентификация клиента через заголовок `X-Client-Id` (`hostname-username`).
- **Пер-клиентские складские алерты**: `get_pending_alerts(client_id)` с изоляцией
  `_sent_by_client`.
- **Полный CRUD по складам в админке**: правка `name`, `capacity`, `orange_threshold`,
  `red_threshold`, `repeat_interval_min`, `current_value`.
- **Скрытие служебного типа `warehouse`** в UI админки (табы «Типы вызовов» и «Создать вызов»).
- **Полное скрытие блока складов** на клиенте при снятой галочке `warehouse` в F1.
- **Аудио-фильтр складов**: при снятой галочке клиент не получает ни алерты, ни визуализацию.
- **Автоинициализация статуса склада** при старте сервера, если склад уже в красной зоне.
- **Отложенная генерация алерта** в `_check_all`, если `_last_filename` ещё не создан.

### Изменено
- **Финальная вычистка рудиментов клиента**:
  - Удалена секция `audio` из `config_client.json`.
  - Удалён ползунок громкости и поле «Звуковой сигнал» из F1.
  - `default_beep.wav` больше не пакуется в `.exe` (остаётся на сервере).
- **Сборка `.exe`**: убран `--add-data "default_beep.wav;."`.
- **Устойчивость цикла синхронизации**: экспоненциальный backoff (5→10→20→30 сек),
  разделённые `except` для timeout / connection / HTTP / JSON.
- **Расположение бейджа обновления**: перенесён в правый фрейм хедера (под часами),
  чтобы не перекрывать заголовок.

### Удалено
- Старый GET-маршрут `/api/admin/close/<external_id>` (заменён на `POST /admin/api/calls/<id>/close`).
- Рудиментный `admin_password` из `config.json` (перенесён в `config_admin.json`).
- Файлы артефактов: `notifier.log` (общий), `notifier_dump.log`.

### Исправлено
- **Гонка напоминаний при нескольких клиентах**: каждый клиент получает напоминания независимо.
- **«Съедание» складских алертов первым клиентом** (было `get_pending_alerts()`, стало `get_pending_alerts(client_id)`).
- **Залипание алертов в очереди**: добавлен `_forget_sent_for_all(filename)` при добавлении в `_pending`.
- **Статус склада «Норма» при старте**, если склад уже превышал порог.
- **Каскадное проигрывание алертов** при возврате галочки: `register_client_activity` синхронизирует трекер.
- **Потеря логов в `.exe`**: `logger.py` узнаёт `.exe` по имени `callnotifierclient.exe`.
- **Ошибка `AttributeError` при отсутствии `self._latest_download_url`** до вызова callback.

### Совместимость
- **Python:** 3.11.9
- **PyInstaller:** 6.22.3 (для сборки клиента)
- **Сервер и клиент:** минорные версии в пределах `1.x.x` совместимы.

## [1.0.0] - 2026-09-30

Первичный релиз после разделения монолита на клиент-серверную архитектуру.

### Добавлено
- Разделение на `server.py` и `client.py`.
- Flask-сервер с `/api/v1/incoming`, `/api/v1/sync`, `/api/v1/audio/<filename>`.
- Silero TTS v5.5 с асинхронной генерацией.
- Менеджер складов с разделением на мгновенные и интервальные алерты.
- Веб-админка `/admin` с 5 табами.
- Полноэкранный Tkinter-клиент с анимацией пульсации.
- Автомиграция конфигов: `config.json` → `config_client.json` + `config_server.json`.
- Разделение логов: `notifier_server.log` / `notifier_client.log`.
