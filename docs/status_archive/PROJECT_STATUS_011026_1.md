# 📊 Текущий статус проекта: CallNotifier v1.0.0

> **Дата фиксации:** 01 октября 2026 г.
> **Архитектурный паттерн:** Распределенная клиент-серверная система (Backend-агностик, Умный локальный GUI-клиент).
> **Текущее состояние:** Стабильное альфа-тестирование. Основные сетевые протоколы обмена, генерации речи и фильтрации Excel-интервалов успешно запущены и проверены тестовыми PowerShell-запросами. Какофония звуков устранена.

---

## 🏗️ 1. Архитектурная карта и связи модулей

### 🖥️ Серверная часть (Фоновая консольная служба)

| Модуль | Назначение |
|---|---|
| **`server.py`** | Главная точка входа. Инициализирует БД, движок речи и фоновые менеджеры. |
| **`database.py`** | Потокобезопасное (`threading.RLock`) хранилище SQLite (`calls.db`). Реализует защиту от гонки сигналов («опережающий стоп»). |
| **`tts_service.py`** | Голосовой движок Silero TTS v5.5. Выполняет асинхронную фоновую генерацию чанков, нормализацию числительных прописью, транслитерацию брендов (`XL -> ИксЭль`) и склейку бесшовных напоминаний (`build_reminder_audio`). |
| **`warehouse_manager.py`** | Фоновый мозг мониторинга. Отслеживает остатки паллет. На основе эмуляционной Excel-модели разделяет алерты на **мгновенные** (при первом пробитии лимита) и **интервальные** (напоминания строго раз в 60 минут без спама промежуточными значениями). |
| **`http_server.py`** | Flask-сервер (REST API). Маршруты:<br>• `POST /api/v1/incoming` — прием данных от внешних систем (АСистем).<br>• `GET /api/v1/sync` — **сердце системы**. Раздает клиентам списки активных вызовов (с учетом фильтра `?types=`), порогов складов и плоский массив готовых аудиофайлов (`warehouse_alerts`).<br>• `GET /api/v1/audio/<filename>` — стриминг статических WAV-файлов. |

### 💻 Клиентская часть (Локальное приложение Tkinter)

| Модуль | Назначение |
|---|---|
| **`client.py`** | Легковесная точка входа. Разворачивает GUI и коннектится к удаленному IP сервера. Не содержит внутри себя тяжелого `torch` и Silero TTS. |
| **`audio.py`** | Локальный менеджер звука. Потоково опрашивает сервер раз в 5 секунд, скачивает недостающие `.wav` в папку `client_cache`, проверяет их валидность по размеру и ставит в бесконечную очередь воспроизведения `pygame.mixer` с защитой от дублирования. |
| **`gui/main_window.py`** (`FullScreenApp`) | Полноэкранный Tkinter-интерфейс. Динамически отрисовывает карточки вызовов, считает время ожидания и обеспечивает плавную анимацию пульсации (синусоидальный glow-эффект) переполненных складов. |
| **`gui/cards.py`** (`RoundedCard`) | Математическая отрисовка карточек со скругленными углами средствами чистого Canvas Tkinter. |
| **`gui/dialogs.py`** (`SettingsDialog`) | Окно конфигурации параметров приложения по клавише `F1`. |

## 🛠️ 2. Закрытые критические баги и рефакторинг

1. **Ликвидация Монолита** — Проект успешно распилен на независимые `server.py` и `client.py`. Сервер стал полностью «немым», воспроизведение завязано строго на клиентах.
2. **Синхронизация методов TTS** — Устранены падения `AttributeError` из-за вызовов несуществующих методов `generate()` (заменено на `generate_chunk()`).
3. **Подавление спама паллет** — Внедрена механика `_last_filename`. При колебаниях остатков на складе (`151 -> 153 -> 154`) сервер не спамит генерацией новых алертов в уши сотрудникам, а обновляет файл в фоне, отдавая его в эфир строго по истечении 60-минутного интервала повтора.
4. **Исправление NameError на клиенте** — Из `audio.py` полностью вычищены старые словари `warehouse_new` / `warehouse_reminders`, вызывавшие падение фонового потока. Клиент переведен на чтение плоского массива `warehouse_alerts`.
