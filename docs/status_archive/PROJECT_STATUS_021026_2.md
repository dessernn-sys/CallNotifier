## 🏗️ 1. Архитектурная карта и связи модулей

### 🖥️ Серверная часть (Фоновая служба, запускается на главном ПК)
Сервер полностью «слепой» и «немой» — у него нет окон Tkinter и аудио-микшера. Он только работает с данными, генерирует файлы и управляет бизнес-логикой.
*   **`server.py`**: Главная точка входа. Инициализирует БД, движок речи, фоновые менеджеры и запускает поток автоочистки кэша.
*   **`database.py`**: Потокобезопасное (`threading.RLock`) хранилище SQLite (`calls.db`). Реализует защиту от гонки сигналов («опережающий стоп») и CRUD-операции для админки.
*   **`tts_service.py`**: Голосовой движок Silero TTS v5.5. Выполняет асинхронную фоновую генерацию чанков, нормализацию числительных прописью, транслитерацию брендов (`XL` -> `ИксЭль`) и склейку бесшовных напоминаний (`build_reminder_audio`). Отдаёт статус занятости через `get_status()`.
*   **`warehouse_manager.py`**: **Фоновый мозг мониторинга**. Отслеживает остатки паллет. Разделяет алерты на мгновенные (при первом пробитии лимита) и интервальные (напоминания строго раз в 60 минут без спама промежуточными значениями). Отдаёт расширенный статус через `get_status()` и поддерживает `force_check()`.
*   **`http_server.py`**: Flask-сервер (REST API + веб-админка). Маршруты:
    *   `POST /api/v1/incoming`: Прием данных от внешних систем (АСистем).
    *   `GET /api/v1/sync`: Сердце системы. Раздает клиентам списки активных вызовов, состояний складов и плоский массив готовых аудиофайлов (`warehouse_alerts`).
    *   `GET /api/v1/audio/<filename>`: Стриминг статических WAV-файлов.
    *   `GET /admin`: Полноценная веб-админка (HTML+CSS+JS), защищена Basic Auth.
    *   `GET /admin/api/*`: JSON-API админки (см. раздел 4).
*   **`config_admin.json`**: Отдельный конфиг **только для сервера**. Содержит `admin_password` и `dispatcher_password` (задел под роль диспетчера). В `.exe`-сборку клиента **не попадает**.

### 💻 Клиентская часть (Локальное приложение, разворачивается на рабочих местах)
Клиент легковесный — не содержит внутри себя тяжелого `torch` и Silero TTS.
*   **`client.py`**: Точка входа для рабочих мест. Разворачивает GUI и коннектится к удаленному IP сервера. Запускает локальный поток очистки кэша.
*   **`audio.py`**: Локальный менеджер звука. Потоково опрашивает сервер раз в 5 секунд, скачивает недостающие `.wav` в папку `client_cache`, проверяет их валидность по размеру и ставит в очередь воспроизведения `pygame.mixer` с защитой от дублирования. Автоматически передает строку разрешенных типов (`?types=`).
*   **`gui/main_window.py` (`FullScreenApp`)**: Полноэкранный Tkinter-интерфейс. Динамически отрисовывает карточки вызовов, считает время ожидания и обеспечивает плавную анимацию пульсации переполненных складов.
*   **`gui/cards.py` (`RoundedCard`)**: Математическая отрисовка карточек со скругленными углами средствами чистого Canvas Tkinter.
*   **`gui/dialogs.py` (`SettingsDialog`)**: Окно конфигурации параметров приложения по клавише **F1**.

### 🌐 Веб-админка сервера (`static/admin/`)
*   **`admin.html`**: Одностраничник с 5 табами (Дашборд, Создать вызов, Типы вызовов, Склады, Логи).
*   **`admin.css`**: Тёмная минималистичная тема, стилистически согласованная с Tkinter-клиентом.
*   **`admin.js`**: Вся клиентская логика: табы, автообновление дашборда (5 сек), живой поток логов (2 сек), тосты, inline-редактирование таблиц.

## 🛠️ 2. Успешно закрытые баги и рефакторинг

1.  **Ликвидация Монолита**: Проект успешно распилен на независимые `server.py` и `client.py`.
2.  **Подавление спама паллет**: Внедрена механика `_last_filename`. При колебаниях остатков на складе сервер не спамит генерацией новых алертов в уши сотрудникам, а обновляет файл в фоне, отдавая его в эфир строго по истечении 60-минутного интервала повтора согласно Excel-модели.
3.  **Исправление `NameError` на клиенте**: Из `audio.py` полностью вычищены старые словари `warehouse_new` / `warehouse_reminders`. Клиент переведен на чтение плоского массива `warehouse_alerts`.
4.  **Устранение ловушки Паттерна «Deep Merge» в `config.py`**: Исправлен баг рекурсивного обновления конфигурации (`elif k in d:` заменено на `else:`). Теперь новые ключи (`allowed_types` и `cache_ttl_days`), которых изначально не было в базовом шаблоне, корректно загружаются из `config.json` и не сбрасываются при перезапуске клиента.
5.  **Фикс краша `AttributeError` по F1**: Исправлена опечатка в вызове метода выбора аудиофайла (`browse_audio`), окно настроек клиента теперь открывается стабильно.
6.  **Разделение конфигов**: Админский пароль вынесен из общего `config.json` в отдельный `config_admin.json`. Рудиментный `admin_password` удалён из `DEFAULT_CONFIG` и из `config.json`. В дальнейшем это позволит собирать `.exe`-клиент **без** админского пароля на борту.
7.  **Замена рудиментной HTML-заглушки `/admin` на полноценную SPA**:
    *   Удалён старый GET-маршрут `/api/admin/close/<external_id>` (нарушение REST и потенциальная CSRF-дыра).
    *   Введён корректный `POST /admin/api/calls/<id>/close`.
    *   Все маршруты `/admin` и `/admin/api/*` защищены `@admin_required` (HTTP Basic Auth).
8.  **Статус-API для подсистем**: В `WarehouseManager` и `TTSService` добавлены методы `get_status()`, дающие админке видимость «мозгов» системы (busy/queue/последний сгенерированный файл/начало превышения порога склада).

## 🌐 4. API-контракты админки

**Базовый URL:** `http://<host>:<port>/admin`
**Аутентификация:** HTTP Basic Auth. Логин игнорируется, важен пароль из `config_admin.json → admin_password`.
**Формат ответа:** JSON, если не указано иное.

### Статика и авторизация

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/admin` | Отдаёт `static/admin/admin.html` (HTML). При отсутствии авторизации возвращает `401` + `WWW-Authenticate: Basic`. |
| GET | `/static/admin/<filename>` | Отдаёт `admin.css`, `admin.js` и прочие ресурсы админки. |

### Дашборд

| Метод | Маршрут | Принимает | Возвращает |
|---|---|---|---|
| GET | `/admin/api/status` | — | `{server: {running, uptime_seconds, host, port, server_time}, tts: {...}, warehouse_manager: {...}, db: {active_calls, types_count}}` |
| GET | `/admin/api/calls` | — | Массив активных вызовов, каждый с добавленным `elapsed_min` |

### Вызовы

| Метод | Маршрут | Принимает | Возвращает |
|---|---|---|---|
| POST | `/admin/api/calls` | `{external_id, type, name, equipment, info, [forced_close_seconds]}` | `{status: "created", external_id}` / `400` |
| POST | `/admin/api/calls/<int:call_id>/close` | — | `{status: "closed", id}` / `404` / `409` |

### Типы вызовов

| Метод | Маршрут | Принимает | Возвращает |
|---|---|---|---|
| GET | `/admin/api/types` | — | Массив типов + поле `active_calls` (кол-во открытых по этому типу) |
| POST | `/admin/api/types` | `{type, description, live_time_min, repeat_interval_min, should_speak}` | `{status: "ok", type}` |
| DELETE | `/admin/api/types/<type_key>` | — | `{status: "ok"}` / `409` (если есть активные вызовы) / `404` |

### Склады

| Метод | Маршрут | Принимает | Возвращает |
|---|---|---|---|
| GET | `/admin/api/warehouses` | — | `{running, warehouses_count, exceeding_count, warehouses: [...]}` |
| POST | `/admin/api/warehouses/<wh_key>/value` | `{value: int}` | `{status: "ok", key, value}` / `400` / `404` |
| POST | `/admin/api/warehouses/force_check` | — | `{status: "ok"}` |

### Логи

| Метод | Маршрут | Принимает | Возвращает |
|---|---|---|---|
| GET | `/admin/api/logs?tail=N` | `N` (1..500, по умолч. 50) | `{lines: [...], tail, log_file}` |
| GET | `/admin/api/logs/download` | — | Скачивание `notifier.log` как файла `notifier_YYYYMMDD_HHMMSS.log` |

## 🚀 5. Дорожная карта развития

### 🔥 Срочные (перед развёртыванием на рабочих местах)

- [ ] **Разделение `config.json` на `config_server.json` и `config_client.json`.**
    *   Устраняет путаницу «`host` для клиента ≠ `host` для сервера».
    *   Позволяет собирать `.exe`-клиент без серверных параметров.
    *   Требуется функция миграции: при первом запуске старый `config.json` раскидывается по двум новым, оригинал переименовывается в `config.json.bak`.
- [ ] **Сборка `.exe`-клиента через PyInstaller.**
    *   **Важно:** путь к конфигу определяется через `sys._MEIPASS`, а не через `__file__`. PyInstaller распаковывает ресурсы во временную папку `AppData\Local\Temp\_MEIxxxxxx`, и `__file__` укажет именно туда — попытка записи по этому пути провалится.
    *   Для пользовательских данных (кэш, лог) использовать `%APPDATA%\CallNotifier\` или рядом с `.exe` (по выбору — обсудить).
    *   `--add-data` для дефолтного `config_client.json`.

### 🛡️ Системные (Отказоустойчивость)

- [ ] **Сетевой иммунитет клиента** — Обернуть `requests.get` в `audio.py` в жёсткий `try...except Exception` с экспоненциальным тайм-аутом, чтобы при падении Wi-Fi/сети клиент не зависал, а уходил в бесконечный цикл мягкого переподключения.
- [ ] **Ротация логов сервера и клиента** — Уже реализована через `RotatingFileHandler` (5 МБ × 3 файла) в `logger.py`. При разделении конфигов убедиться, что логи сервера и клиента пишутся **в разные файлы** (сейчас оба компонента пишут в `notifier.log`, что при разделении на разные машины станет неактуально).
- [ ] **Автоматический клининг кэша (TTL)** — Уже реализован на обеих сторонах (сервер и клиент, раз в 6 часов, TTL из `config.json → display.cache_ttl_days`).

## 📌 6. Важное примечание по `.exe`-сборке

Когда PyInstaller собирает скрипт в `.exe`, он распаковывает временные файлы (включая дефолтный конфиг, если мы его зашьём) в скрытую системную папку `AppData\Local\Temp\_MEIxxxxxx`. Если в коде прописан путь через `__file__`, программа начнёт искать файлы там и выдаст ошибку записи.

**Решение (применить при разделении конфигов и сборке):**
*   Путь к **ресурсам внутри дистрибутива** (дефолтный `config_client.json`) определяется через:
    ```python
    import sys, os
    if getattr(sys, 'frozen', False):
        base_path = sys._MEIPASS
    else:
        base_path = os.path.dirname(os.path.abspath(__file__))
    ```
*   Путь к **пользовательским данным** (перезаписываемый конфиг, `client_cache`, `notifier.log`) — вынести в `%APPDATA%\CallNotifier\` или рядом с `.exe` (окончательно решить на этапе сборки).

## 📎 7. Быстрый старт для тестирования админки

```bash
# Health-check (без авторизации)
curl http://<host>:<port>/health

# 401 без пароля
curl -i http://<host>:<port>/admin/api/status

# Полный статус системы
curl -u admin:<password> http://<host>:<port>/admin/api/status

# Создание вызова через файл (надёжно для кириллицы в Git Bash)
cat > /tmp/call.json << 'EOF'
{
  "external_id": "manual-001",
  "type": "manager",
  "name": "Иванов",
  "equipment": "Станок №5",
  "info": "Тестовый вызов"
}
EOF
curl -u admin:<password> -X POST http://<host>:<port>/admin/api/calls \
     -H "Content-Type: application/json" \
     --data-binary @/tmp/call.json

# Закрытие вызова (заменить <id> на фактический)
curl -u admin:<password> -X POST http://<host>:<port>/admin/api/calls/<id>/close

# Открыть в браузере
# http://<host>:<port>/admin
# Логин: admin, пароль: из config_admin.json
```
