## 🏗️ 1. Архитектурная карта и связи модулей

### 🖥️ Серверная часть (Фоновая служба, запускается на главном ПК)
Сервер полностью «слепой» и «немой» — у него нет окон Tkinter и аудио-микшера. Он только работает с данными, генерирует файлы и управляет бизнес-логикой.
*   **`server.py`**: Главная точка входа. Инициализирует БД, движок речи, фоновые менеджеры и запускает поток автоочистки кэша.
*   **`database.py`**: Потокобезопасное (`threading.RLock`) хранилище SQLite (`calls.db`). Реализует защиту от гонки сигналов («опережающий стоп»).
*   **`tts_service.py`**: Голосовой движок Silero TTS v5.5. Выполняет асинхронную фоновую генерацию чанков, нормализацию числительных прописью, транслитерацию брендов (`XL` -> `ИксЭль`) и склейку бесшовных напоминаний (`build_reminder_audio`).
*   **`warehouse_manager.py`**: **Фоновый мозг мониторинга**. Отслеживает остатки паллет. Разделяет алерты на мгновенные (при первом пробитии лимита) и интервальные (напоминания строго раз в 60 минут без спама промежуточными значениями).
*   **`http_server.py`**: Flask-сервер (REST API). Маршруты:
    *   `POST /api/v1/incoming`: Прием данных от внешних систем (АСистем).
    *   `GET /api/v1/sync`: Сердце системы. Раздает клиентам списки активных вызовов, состояний складов и плоский массив готовых аудиофайлов (`warehouse_alerts`).
    *   `GET /api/v1/audio/<filename>`: Стриминг статических WAV-файлов.

### 💻 Клиентская часть (Локальное приложение, разворачивается на рабочих местах)
Клиент легковесный — не содержит внутри себя тяжелого `torch` и Silero TTS.
*   **`client.py`**: Точка входа для рабочих мест. Разворачивает GUI и коннектится к удаленному IP сервера. Запускает локальный поток очистки кэша.
*   **`audio.py`**: Локальный менеджер звука. Потоково опрашивает сервер раз в 5 секунд, скачивает недостающие `.wav` в папку `client_cache`, проверяет их валидность по размеру и ставит в очередь воспроизведения `pygame.mixer` с защитой от дублирования. Автоматически передает строку разрешенных типов (`?types=`).
*   **`gui/main_window.py` (`FullScreenApp`)**: Полноэкранный Tkinter-интерфейс. Динамически отрисовывает карточки вызовов, считает время ожидания и обеспечивает плавную анимацию пульсации переполненных складов.
*   **`gui/cards.py` (`RoundedCard`)**: Математическая отрисовка карточек со скругленными углами средствами чистого Canvas Tkinter.
*   **`gui/dialogs.py` (`SettingsDialog`)**: Окно конфигурации параметров приложения по клавише **F1**.

## 🛠️ 2. Успешно закрытые баги и рефакторинг

1.  **Ликвидация Монолита**: Проект успешно распилен на независимые `server.py` и `client.py`. 
2.  **Подавление спама паллет**: Внедрена механика `_last_filename`. При колебаниях остатков на складе сервер не спамит генерацией новых алертов в уши сотрудникам, а обновляет файл в фоне, отдавая его в эфир строго по истечении 60-минутного интервала повтора согласно Excel-модели.
3.  **Исправление `NameError` на клиенте**: Из `audio.py` полностью вычищены старые словари `warehouse_new` / `warehouse_reminders`. Клиент переведен на чтение плоского массива `warehouse_alerts`.
4.  **Устранение ловушки Паттерна «Deep Merge» в `config.py`**: Исправлен баг рекурсивного обновления конфигурации (`elif k in d:` заменено на `else:`). Теперь новые ключи (`allowed_types` и `cache_ttl_days`), которых изначально не было в базовом шаблоне, корректно загружаются из `config.json` и не сбрасываются при перезапуске клиента.
5.  **Фикс краша `AttributeError` по F1**: Исправлена опечатка в вызове метода выбора аудиофайла (`browse_audio`), окно настроек клиента теперь открывается стабильно.

## 📅 3. Текущий этап: Расширенная веб-админка сервера Flask (`/admin`)

**Цель этапа:** Превратить простую статическую HTML-страничку сервера в интерактивный пульт управления системой для администратора, полностью исключающий необходимость ручной отправки тестовых POST-запросов через PowerShell.

### Компоненты для реализации:
1.  **Интерфейс (UI):** Перевод страницы на современный, чистый и scannable CSS-шаблон (встроенный в код Flask, без внешних CDN, для работы в изолированной локальной сети предприятия).
2.  **Управление вызовами (CRUD):** 
    *   Возможность ручного создания вызова через веб-форму (эмуляция АСистем).
    *   Кнопка мгновенного закрытия любого активного вызова.
3.  **Управление типами вызовов:** 
    *   Таблица существующих в БД типов (`manager`, `mechanic` и т.д.) с возможностью изменения их параметров (интервал повтора, время жизни вызова).
4.  **Фоновый мониторинг системы:**
    *   Вывод текущего статуса фонового потока Silero TTS и менеджера складов.
    *   Интеграция окна живого просмотра (логов) — вывод последних 50 строк из файла `notifier.log`.

## И маленькое, но важное замечание:
#### .exe-сборку клиента имеет смысл планировать через PyInstaller с --add-data для config_client.json. Об этом поговорим, когда дойдёт до сборки — просто держите в голове, что путь к config.json в .exe определяется через sys._MEIPASS, а не через `__file__`. Это тоже учтём при разделении конфигов.
#### Пояснение: Когда PyInstaller собирает скрипт в .exe, он распаковывает временные файлы (включая дефолтный конфиг, если мы его зашьем) в скрытую системную папку AppData\Local\Temp\_MEIxxxxxx. Если в коде прописан путь через `__file__`, программа начнет искать файлы там и выдаст ошибку записи.
