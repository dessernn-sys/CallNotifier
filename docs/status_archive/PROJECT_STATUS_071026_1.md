## 🏗️ 1. Архитектурная карта и связи модулей

### 🖥️ Серверная часть (Фоновая служба, запускается на главном ПК)
Сервер полностью «слепой» и «немой» — у него нет окон Tkinter и аудио-микшера.
*   **`server.py`**: Главная точка входа. Инициализирует `ServerConfig`, `AdminConfig`, БД, движок речи, фоновые менеджеры и запускает поток автоочистки кэша.
*   **`database.py`**: Потокобезопасное (`threading.RLock`) хранилище SQLite (`calls.db`). Реализует защиту от гонки сигналов («опережающий стоп») и CRUD-операции для админки.
*   **`tts_service.py`**: Голосовой движок Silero TTS v5.5. Асинхронная фоновая генерация чанков, нормализация числительных, транслитерация брендов (`XL → ИксЭль`), склейка бесшовных напоминаний (`build_reminder_audio`). Отдаёт статус занятости через `get_status()`.
*   **`warehouse_manager.py`**: **Фоновый мозг мониторинга складов**. Разделяет алерты на мгновенные (первое превышение) и интервальные. Отдаёт расширенный статус через `get_status()`, поддерживает `force_check()`, `reload_from_db()` и **per-client** выдачу алертов через `get_pending_alerts(client_id)`.
*   **`http_server.py`**: Flask-сервер (REST API + веб-админка). Маршруты:
    *   `POST /api/v1/incoming`: Приём данных от внешних систем (АСистем).
    *   `GET /api/v1/sync`: Раздаёт клиентам списки активных вызовов, состояние складов, напоминания и плоский массив складских алертов. Учитывает фильтр `?types=` и заголовок `X-Client-Id`.
    *   `GET /api/v1/audio/<filename>`: Стриминг WAV-файлов.
    *   `GET /api/v1/version`: Актуальная версия клиента, URL и sha256 релиза.
    *   `GET /admin`: Веб-админка (HTML+CSS+JS), защищена Basic Auth.
    *   `GET /admin/api/*`: JSON-API админки (см. раздел 4).
*   **`config_server.json`**: Серверный конфиг: `http_server` (на каком интерфейсе слушать), `display.cache_ttl_days`, `warehouse`.
*   **`config_admin.json`**: Отдельный конфиг **только для сервера**: `admin_password`, `dispatcher_password` (задел под роль диспетчера).
*   **`notifier_server.log`**: Серверный лог.

### 💻 Клиентская часть (Локальное приложение, разворачивается на рабочих местах)
Клиент легковесный — не содержит `torch` и Silero TTS.
*   **`client.py`**: Точка входа. Разворачивает GUI, инициализирует `ClientConfig`, коннектится к серверу, запускает поток очистки кэша.
*   **`audio.py`**: Локальный менеджер звука. Опрашивает сервер раз в 5 секунд, скачивает WAV в `client_cache`, ставит в очередь `pygame.mixer`. Устойчив к сбоям: экспоненциальный backoff при потере сети, разделённые исключения, защита от невалидного JSON. Передаёт `X-Client-Id` (hostname-username). Отслеживает версию сервера через callback.
*   **`gui/main_window.py` (`FullScreenApp`)**: Полноэкранный Tkinter-интерфейс. Отрисовывает карточки вызовов, анимация пульсации переполненных складов, **бейдж «Доступно обновление»** в правом верхнем углу. Скрывает/показывает блок складов в зависимости от фильтра F1.
*   **`gui/cards.py` (`RoundedCard`)**: Отрисовка карточек со скруглёнными углами на чистом Canvas Tkinter.
*   **`gui/dialogs.py` (`SettingsDialog`)**: Окно F1. Содержит только: IP/порт сервера, TTL кэша, фильтр типов вызовов.
*   **`config_client.json`**: Клиентский конфиг: `http_server`, `display` (включая `allowed_types`).
*   **`notifier_client.log`**: Клиентский лог (в `%APPDATA%\CallNotifier\` при `.exe`).

### 🌐 Веб-админка сервера (`static/admin/`)
*   **`admin.html`**, **`admin.css`**, **`admin.js`** — одностраничник с 5 табами: Дашборд, Создать вызов, Типы вызовов, Склады, Логи.

### 📦 Релизы клиента (`static/client/`)
*   **`CallNotifierClient-<version>.exe`** — готовые сборки клиента. Сервер отдаёт их через `/static/client/...`. Актуальная версия определяется по имени файла.

## 🛠️ 2. Успешно закрытые баги и рефакторинг

1.  **Ликвидация Монолита**: Проект распилен на независимые `server.py` и `client.py`.
2.  **Подавление спама паллет**: Внедрена механика `_last_filename`. Сервер обновляет файл в фоне, но отдаёт его в эфир строго по интервалу повтора.
3.  **Исправление `NameError` на клиенте**: Из `audio.py` вычищены старые словари `warehouse_new` / `warehouse_reminders`. Клиент переведён на плоский массив `warehouse_alerts`.
4.  **Устранение ловушки Deep Merge в `config.py`**: Исправлено рекурсивное обновление конфигурации (`elif k in d:` → `else:`).
5.  **Фикс краша `AttributeError` по F1**: Исправлен вызов `browse_audio`.
6.  **Разделение конфигов**: `config.json` → `config_client.json` + `config_server.json` + `config_admin.json`. Автомиграция со старого файла в `.bak`.
7.  **Разделение логов**: `notifier_server.log` / `notifier_client.log`. При `.exe` — логи и кэш в `%APPDATA%\CallNotifier\`.
8.  **Сетевой иммунитет клиента**: Экспоненциальный backoff (5→10→20→30 сек), разделённые `except` для timeout/connection/HTTP/JSON, устойчивость к невалидным данным.
9.  **Замена рудиментной заглушки `/admin` на полноценную SPA** с Basic Auth. Удалён старый GET-маршрут `/api/admin/close/<external_id>`.
10. **Статус-API подсистем**: `WarehouseManager.get_status()` и `TTSService.get_status()` для админки.
11. **Фикс потери логов в `.exe`**: В `logger.py` определение роли процесса переписано на проверку имени `.exe` (`callnotifierclient.exe`), fallback — `%APPDATA%`.
12. **Устранение «гонки» напоминаний вызовов**: Введён трекер `_last_reminder_sent[(client_id, external_id)]`. Каждый клиент получает напоминания независимо.
13. **Устранение «гонки» складских алертов**: `get_pending_alerts(client_id)` с per-client трекером `_sent_by_client`.
14. **Фикс «залипания» алертов в очереди**: `_forget_sent_for_all(filename)` при добавлении в `_pending_reminders`/`_pending_new` — файл «забывается» у всех клиентов, повторы играются.
15. **Фикс статуса склада при старте сервера**: `_load_warehouses` и `reload_from_db` теперь инициализируют `_exceedance_start`, если склад уже в красной зоне. Отложенная генерация алерта в `_check_all` при отсутствии `_last_filename`.
16. **Фикс каскада после возврата галочки**: `register_client_activity(client_id)` синхронизирует `_sent_by_client` с текущим `_pending`, чтобы при возврате фильтра клиент не получил накопленное.
17. **Вычистка рудиментов клиента**: Удалена секция `audio` из `config_client.json`, ползунок громкости и поле «Звуковой сигнал» из F1, `default_beep.wav` из `.exe`.
18. **Механизм версий**: `__version__` в `config.py`, `GET /api/v1/version`, `server_version` в `sync`, бейдж «🔔 Доступно обновление» в хедере клиента.
19. **Полное скрытие блока складов**: При отсутствии складов в фильтре F1 клиент сжимает блок до 1 px (визуально невидим).

## 🧩 3. Реализованные фичи (справочник)

### Веб-админка `/admin`
*   5 табов: Дашборд, Создать вызов, Типы вызовов, Склады, Логи.
*   Basic Auth из `config_admin.json`.
*   Полный CRUD по складам (name, capacity, orange/red thresholds, repeat_interval_min, current_value).
*   CRUD по типам вызовов с защитой от удаления используемых типов.
*   Ручное создание вызовов с режимом «пакетной рассылки».
*   Живой лог (polling 2 сек), скачивание лога.

### Клиент `.exe`
*   Сборка через PyInstaller: `--onefile --windowed --add-data config_client.json`.
*   Хранение данных: конфиг рядом с `.exe`, кэш и логи — в `%APPDATA%\CallNotifier\`.
*   Гибридные пути через `sys._MEIPASS` и `sys.frozen`.
*   Бейдж обновления в хедере.

### Фильтр типов вызовов (F1)
*   Клиент передаёт `?types=` в `/api/v1/sync`.
*   Сервер фильтрует `calls` и `warehouse_alerts`/`warehouses` по списку.
*   Складские алерты **и визуализация** отключаются при снятой галочке `warehouse`.

## 📌 6. Важные заметки

### `.exe`-сборка

PyInstaller распаковывает ресурсы в `AppData\Local\Temp\_MEIxxxxxx`. Путь через `__file__` указывает туда, запись провалится. Используется:
```python
if getattr(sys, 'frozen', False):
    base_path = sys._MEIPASS
else:
    base_path = os.path.dirname(os.path.abspath(__file__))
```

Для пользовательских данных:
```python
if getattr(sys, 'frozen', False):
    base = os.environ.get('APPDATA')
    path = os.path.join(base, 'CallNotifier')
```

### Пароли

`config_admin.json` содержит `admin_password` (используется) и `dispatcher_password` (задел).
